# usability_findings — 一般社員が使う場面での誤解・迷い・矛盾（step 3）

前提（受領した TASK の context.premises）: 利用者は特別なツールを持たない社内の一般社員で、ChatGPT / Gemini / Copilot などのYAMLを読めるAIで使う。
「検証した」は、仕様の文面の照合、YAML の読み込み試験、または受領した実物のパケットで再現を確認したもの。「推論した」は、場面を想定して導いたもので、実際の利用者では確かめていない。

## 受領した TASK パケット（TASK-20260925-spec-improve）の事前点検

13節1項に従い、実行前に14節で点検した。

| チェックリスト | error | warning | 内容 |
|---|---:|---:|---|
| 原本 v2.0 | 1 | 0 | `meta.kd` が欠けている（`spec_version` と書かれている） |
| 改訂案 v2.1 | 2 | 3 | 上記に加え、`inputs.read_only` がない（error）。仕様外の最上位キーが3つ（discovery / mutation / note）（warning） |

13節1項を文字どおりに読むと、実行せずに報告することになる。しかし、この不備は仕様の欠陥を見つけるという本タスクの対象そのものであり、依頼の意図は読み取れる。作業も create_only（既存のものは変えない）と宣言されている。そのため、**実行したうえで、この不備を所見として記録した**。この判断と理由は KD_result.yaml の B002（DECISION）に記録している。
